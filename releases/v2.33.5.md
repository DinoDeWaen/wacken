# Wacken Planner 2026 V2.33.5

## Scope

This signed Android hotfix delivers TASK-199 on top of V2.33.4:

- Leave YouTube and Spotify actions empty when no channel or artist is stored, including new bands such as Abbie Falls.
- Treat JSON null metadata as absent on Android instead of displaying the text `null` or generating a Spotify `artist/null` link.
- Correct stale cached links on a successful sync while preserving known links, ratings and band history.
- Allow reviewed metadata proposals to fill genuinely empty fields without overwriting known values.

The database already stores Abbie Falls' unknown metadata correctly. No catalog rewrite, guessed channel, new migration or key rotation is included. The atomic festival creation fix from V2.33.4 remains included.

## Install and use

Install the attached **app-release.apk** over V2.33.4, then use **Sync from Supabase** and reopen the band. Unknown YouTube/Spotify actions should be absent; bands with stored links keep them. Both releases use the same stable certificate, allowing an in-place update. Retain pending ratings by updating without uninstalling or clearing Android storage.

## APK and build

Official artifact: `app/build/outputs/apk/release/app-release.apk`.

```text
package be.wacken.planner
versionCode 41
versionName 2.33.5
minSdkVersion 23
targetSdkVersion 36
```

Use JDK 21, Android SDK 36, Docker, Python 3, curl and a connected emulator. Configure the four local `WACKEN_RELEASE_*` signing values from macOS Keychain, using the existing stable gitignored keystore.

```bash
scripts/ensure-release-keystore.sh
scripts/verify-festival-creation.sh
./gradlew clean test qaTest :app:connectedDebugAndroidTest \
  :app:lintVitalRelease assembleRelease --no-daemon
```

TASK-200 records the verified APK digest, signing certificate, metadata, command results, upgrade observations and release URL.

## Validation and accepted limits

The release gates include ten real PostgreSQL/PostgREST scenarios with SQL rollback/permission assertions and fifteen Android tests. Five native Android regressions cover null creation/cache publication, sync correction and actual detail actions, known links, missing/blank fields and reviewed metadata. Three failed before TASK-199's fix. Android-native tests are necessary because the desktop JSON library handles null differently.

Unit/QA/coverage, release lint-vital, a fresh signed build and in-place upgrade smoke checks are required before publication. Physical-phone external-browser and YouTube-app interaction remains unobserved; this fix removes unknown actions and does not check whether every stored remote channel remains live.

Play Store distribution, automatic channel discovery and unrelated features remain outside this release. Existing full lintDebug NewApi errors and Supabase security-advisor findings are unchanged. Installations signed by the lost older release key require a one-time reinstall only after protecting local-only data; the current stable-key releases update each other.
