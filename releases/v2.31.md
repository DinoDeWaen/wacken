# Wacken Planner 2026 V2.31

## Scope

V2.31 is an official signed Android release for the completed reviewed external
metadata provider set after V2.30.

Changes since V2.30:

- Adds Wikidata as an external metadata provider for reviewed image, Spotify,
  and YouTube proposals from structured item claims.
- Adds Wikipedia as an external metadata provider for reviewed neutral
  biography and page-summary image proposals.
- Adds optional Spotify Web API enrichment for reviewed artist URL and image
  proposals when `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET` are configured.
- Adds optional YouTube Data API enrichment for reviewed channel URL proposals
  when `YOUTUBE_API_KEY` is configured.
- Completes the imported known-band linking defect scope by closing the full
  MusicBrainz/Wikidata/Wikipedia/Spotify/YouTube metadata provider set.
- Adds a V2.31 user acceptance test overview for reviewed band linking and
  metadata enrichment checks.
- Bumps Android release metadata to `versionCode 34` and `versionName 2.31`.

No Supabase schema, persistence migration, schedule logic, automatic unreviewed
merge behavior, or Play Store distribution behavior changed in this release.

## Signing And Installation

V2.31 uses the stable local V2.9+ release-key line managed by
`scripts/ensure-release-keystore.sh`.

Install it over a release that uses the same stable signing key. Devices still
using an APK signed before the stable key was introduced must uninstall the old
app once, install V2.31, and then sync from Supabase. Future releases signed by
this key will update normally.

MusicBrainz, Wikidata, and Wikipedia metadata lookup do not require API keys,
but production-like builds should provide a meaningful maintainer User-Agent:

```bash
MUSICBRAINZ_USER_AGENT="WackenPlanner/2.31 ( contact@example.com )" ./gradlew assembleRelease
```

Spotify enrichment is optional and requires `SPOTIFY_CLIENT_ID` and
`SPOTIFY_CLIENT_SECRET` at build time. YouTube enrichment is optional and
requires `YOUTUBE_API_KEY` at build time. Do not ship production Spotify secrets
in a broadly distributed mobile APK without moving token exchange behind a
backend.

## User Acceptance Test Overview

The V2.31 user acceptance overview is maintained in:

```text
backlog/docs/v2.31-user-acceptance-test-overview.md
```

Manual release acceptance should cover:

- Reviewed imported-band linking for spelling/case variants such as
  `Any Given Day` vs `Any given Day`.
- Own-catalog metadata proposals before any online lookup.
- Reviewed external metadata proposals from MusicBrainz, Wikidata, Wikipedia,
  optional Spotify, and optional YouTube.
- Optional-provider behavior when Spotify or YouTube configuration is absent.
- No automatic overwrite of existing biography, picture, Spotify, or YouTube
  metadata.

## Known Non-Goals

- No Play Store distribution in V2.31.
- No Supabase schema change in V2.31.
- No automatic unreviewed fuzzy band merges.
- No automatic metadata overwrite behavior.
- No production secrets committed for Spotify or YouTube provider access.
- No final Summer Breeze stages, performances, distances, or food import data.

## Accepted Risks

- Optional Spotify and YouTube providers require configured credentials; when
  absent, they are reported as not configured and the rest of the metadata
  workflow continues.
- Live external metadata availability is not guaranteed during festival field
  use; existing cached/catalog metadata remains available when lookup fails.
- Devices still using an APK signed before the stable key was introduced must
  uninstall once before installing V2.31.
