# Wacken Planner 2026 V2.30

## Scope

V2.30 is an official signed Android release for the latest festival
administration and reviewed metadata cleanup work after V2.29.

Changes since V2.29:

- Requires an explicit non-blank festival name when adding a new festival from
  CSV.
- Adds Settings support for renaming the active festival while preserving the
  festival identity.
- Adds reviewed imported-band linking for active-festival lineups, including
  fuzzy/case-insensitive candidate discovery, editable search terms, candidate
  dropdowns, and an explicit no-match option.
- Adds a reviewed band metadata proposal framework that checks the own band
  catalog first, requires approval before saving, and never overwrites existing
  metadata automatically.
- Adds MusicBrainz as the first external metadata provider for reviewed artist
  URL relationship proposals, including Spotify and YouTube links when present.
- Adds backlog stories for the remaining metadata providers: Wikidata,
  Wikipedia, Spotify, and YouTube.
- Bumps Android release metadata to `versionCode 33` and `versionName 2.30`.

No Supabase schema, persistence migration, schedule logic, or Play Store
distribution behavior changed in this release.

## Signing And Installation

V2.30 uses the stable local V2.9+ release-key line managed by
`scripts/ensure-release-keystore.sh`.

Install it over a release that uses the same stable signing key. Devices still
using an APK signed before the stable key was introduced must uninstall the old
app once, install V2.30, and then sync from Supabase. Future releases signed by
this key will update normally.

MusicBrainz metadata lookup does not require an API key, but production-like
builds should provide a meaningful maintainer User-Agent:

```bash
MUSICBRAINZ_USER_AGENT="WackenPlanner/2.30 ( contact@example.com )" ./gradlew assembleRelease
```

## Known Non-Goals

- No Play Store distribution in V2.30.
- No Supabase schema change in V2.30.
- No automatic unreviewed fuzzy band merges.
- No automatic metadata overwrite behavior.
- No Wikidata, Wikipedia, Spotify Web API, or YouTube Data API provider
  integration yet; those remain separate backlog stories.
- No final Summer Breeze stages, performances, distances, or food import data.

## Accepted Risks

- MusicBrainz can provide artist identity and URL relationships, but biography
  and image enrichment still require later Wikidata/Wikipedia work.
- MusicBrainz live availability is not guaranteed during festival field use;
  existing cached/catalog metadata remains available when lookup fails.
- Devices still using an APK signed before the stable key was introduced must
  uninstall once before installing V2.30.
