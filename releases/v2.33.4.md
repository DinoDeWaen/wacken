# Wacken Planner 2026 V2.33.4

## Scope

This signed Android hotfix delivers TASK-197 on top of V2.33.3:

- Fix Add Festival with the complete 63-band Summer Breeze CSV. Different exact names such as `Any Given Day` and `Any given Day` receive distinct identities without overwriting shared metadata or history.
- Save the festival, bands, lineup and personal planning-rating prefill in one authorized database transaction. Failed writes roll back together.
- Safely confirm an interrupted request by retrying the same festival name and CSV, without duplicating data or resetting later ratings.
- Publish the complete result to Room in one transaction and preserve pending rating edits. Reject malformed CSV headers or blank band names before creation.
- Validate real database constraints, permissions, rollback and concurrency, plus the Android screen and cache, in mandatory CI/release gates.

Flyway V013 is already deployed. The incomplete Summer breeze import has been recovered with all 63 bands; prior metadata and ratings were preserved. See the [incident analysis](../backlog/docs/add-festival-creation-incident-2026-10-16.md) for the causes, introducing changes and coverage gaps.

## Install and use

Install the attached **app-release.apk** over V2.33.3. Both use the stable release certificate; retain app data and pending edits by updating in place. Do not uninstall or clear Android storage while ratings are pending.

Use **Sync from Supabase** to load the recovered Summer breeze festival. For a future festival, archive the current active festival, open **Add Festival**, enter its name, choose a valid bands CSV, and wait for confirmation. If the response is interrupted, retry the identical name and CSV to confirm the result. Other group members can then sync the complete lineup.

## APK and build

Official artifact: `app/build/outputs/apk/release/app-release.apk`.

```text
package be.wacken.planner
versionCode 40
versionName 2.33.4
minSdkVersion 23
targetSdkVersion 36
```

Use JDK 21, Android SDK 36, Docker, Python 3, curl, and a connected emulator. Configure the four `WACKEN_RELEASE_*` signing values from the local macOS Keychain; the stable keystore remains gitignored. No signing secrets are included in the release.

```bash
scripts/ensure-release-keystore.sh
scripts/verify-festival-creation.sh
./gradlew clean test qaTest :app:connectedDebugAndroidTest \
  :app:lintVitalRelease assembleRelease --no-daemon
```

The verified APK digest, stable certificate, upgrade evidence and command outcomes are recorded in TASK-198.

## Validation and limits

Release gates cover ten real PostgreSQL/PostgREST HTTP scenarios, SQL failure injection and authorization assertions, and ten Android instrumentation tests, including six creation UI/Room cases. Unit/QA/coverage, release lint-vital and a fresh signed build are required before publication. The release task records APK signature/metadata checks and the in-place upgrade smoke test.

The remote operation and local cache are separate transaction boundaries: a cache failure retains the complete remote result and previous cache until the identical request is retried. Exact-name matching is intentional; case variants are separate bands until reviewed linking is approved.

The reported physical phone's document-picker interaction remains unverified. Existing full `lintDebug` NewApi errors and Supabase security-advisor findings are unchanged; release lint-vital passes. Play Store distribution, unrelated features, key rotation and automatic fuzzy merges are outside this release.

Installations signed with the older lost release key cannot update in place. Those devices need a one-time reinstall only after protecting any local-only data. Builds from the current stable key line can update each other.
