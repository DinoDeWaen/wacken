# Wacken Planner 2026 V2.33.3

## Scope

This signed Android update includes TASK-195 on top of V2.33.2:

- Adding a festival from a bands CSV now performs Supabase writes in the background, with progress and useful failure feedback.
- Members of the shared group can create an active festival, add new bands, and save its lineup. Existing bands are reused without requiring band-metadata update permission.
- A rejected festival creation request leaves the existing local cache usable.

The V012 group-member creation policy is already deployed to the shared Supabase project. V2.33.3 includes the matching migration source.

## Install and use

Install the attached `app-release.apk` over V2.33.2 to retain app data and pending changes. Both builds use the same stable release certificate. Do not uninstall or clear Android storage while a rating is pending.

After archiving or deleting the old active festival, open **Add Festival**, enter a name, choose a valid bands CSV, and tap **Add festival from bands.csv**. Wait for the group-wide result. Sync another group member's device to see the new festival and lineup.

## Validation

- Android worker and Supabase request regression tests, full unit and QA suites, and the signed release build must pass.
- The V012 RLS transaction test passed for member creation and non-member denial during TASK-195; Flyway validated all 12 migrations.
- `apksigner` verified v1/v2 signatures; `aapt` confirmed package, version, and minimum SDK. The emulator accepted `adb install -r` over the published V2.33.2 APK, retained its original install time and app data directory, and launched V2.33.3. See TASK-196 for the complete evidence.

## Limits and accepted risks

The festival creation workflow uses several remote requests. A network failure after the first insert can leave a partial remote festival that needs support to clean up before retrying. A physical-device CSV walkthrough was not available during TASK-195 and remains a release smoke test.

Play Store distribution and key rotation are outside this release. Installations signed with the older lost release key cannot update in place; those devices need one uninstall and reinstall after exporting any local-only data. The current stable key supports in-place updates from V2.33 onward.
