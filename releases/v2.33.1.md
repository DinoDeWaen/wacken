# Wacken Planner 2026 V2.33.1

## Scope

This signed Android hotfix contains two fixes since V2.33:

- Group members can archive the active festival; the app reports progress and
  any Supabase error.
- Sync detects a pending planning rating whose stored festival no longer exists
  in Supabase. It shows the band, stars, and festival ID. After the user confirms
  that the rating belongs to Wacken 2026, the app checks for a conflicting
  Wacken rating, moves the pending row locally, and retries sync.

No Supabase schema, account, or group policy changes are included.

## APK and version

The GitHub release attaches the signed `app-release.apk` built at
`app/build/outputs/apk/release/app-release.apk` with JDK 21.

```text
package be.wacken.planner
versionCode 37
versionName 2.33.1
minSdkVersion 23
targetSdkVersion 36
```

The APK uses the same stable local release signing key as V2.33. Install it
over a V2.33 installation signed by that key to retain the phone's pending
rating and other app data. Do not uninstall the app or use Android **Clear
storage/data** while a rating is pending.

## Recover the pending rating

1. Install V2.33.1 over the current app, then open it and tap **Sync from
   Supabase** in Settings or use the home screen sync action.
2. Review the dialog's band, star rating, and stored festival ID. Tap **Move to
   Wacken 2026** only if that rating belongs to Wacken Open Air 2026.
3. The app checks both the local cache and Supabase for an existing Wacken rating
   for that band, then retries sync. Verify that the pending count decreases.
4. If a conflict or connection error appears, the rating stays pending. Keep
   the app data and report the dialog details for a follow-up repair.

Sync the pending rating before using **Archive**. Recovery deliberately stops
if Wacken is already archived.

## Build and validation

Build with the stable gitignored release keystore and the four signing values
stored in the local macOS Keychain:

```bash
JAVA_HOME=$(/usr/libexec/java_home -v 21) ./gradlew clean \
  :domain:test :application:test :infrastructure:test \
  :app:testDebugUnitTest qaTest :app:compileDebugJavaWithJavac assembleRelease
```

Verify the APK using Android SDK `apksigner` and `aapt`; record its SHA-256 in
TASK-191. The verified APK SHA-256 is
`a2be471a439f440eb28eb1f2d9a1909768d2a32a2cf940c1230c3ad28cd2b6b8`.
`apksigner` confirms v1/v2 signatures and the same certificate digest as
V2.33. An emulator accepted an `adb install -r` update from V2.33 and retained
the original package install time. Android lint still reports 14 existing
`NewApi` errors, with none introduced by this hotfix.

## Known limits

The affected phone was not attached for a device test. The app cannot know
whether an orphaned rating was intended for Wacken without the user's review.
An APK signed with an older, lost certificate cannot be updated in place by
this signing key; uninstalling that older app would remove local-only data.
