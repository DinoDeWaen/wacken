# Wacken Planner 2.35.1

Patch release including the completed ArchUnit architecture checks in the release
source. App features and rating behavior remain those of 2.35.

## Changes

- Pinned test-only ArchUnit 1.5.1 checks compiled JVM domain/application/
  infrastructure dependency boundaries, framework leaks and inter-layer cycles.
- Complete, nonempty main-bytecode imports and compiled positive/negative
  fixtures protect the checks from silent passes. Ordinary Gradle test/check and
  required CI execute them. See [ADR0023](https://github.com/DinoDeWaen/wacken/blob/v2.35.1/backlog/decisions/0023-archunit-jvm-boundary-tests.md).
- ArchUnit adds no production dependency. It complements the Groma semantic gate;
  Android adapter bytecode, within-layer cycles and unused-code proof remain
  outside its scope. No database migration or product workflow change.

## APK and validation

- Package: `be.wacken.planner`; versionName `2.35.1`, versionCode `44`.
- Minimum Android API23; target/compile API36.
- Official signed asset: `app-release.apk`; source tag: `v2.35.1`.
- Stable certificate SHA256:
  `ede2ae97735a305900e87bc0fdc021c03382db4e30435f2349a96a3fdcc7545f`.
- Build: clean checkout, `./gradlew test qaTest assembleRelease --rerun-tasks`.
- Attached `SHA256SUMS` and `release-validation.json` bind the exact APK/source,
  CI gates, baseline and signed upgrade. `upgrade-evidence.zip` contains retained
  state probe results, package metadata and signature checks.
- JVM/ArchUnit/QA/coverage/lint, Groma, disposable real database/API and native
  API23/API36 gates are required before publication. Existing environment-gated
  unit integration skips are reported separately from dedicated real gate passes.
- Exact published2.35/code43 →2.35.1/code44 signed update verifies login/cache,
  pending operations, member-specific opinions, festival planning/after values,
  dated history, corrections and normal offline startup. A negative control
  rejects the old version before installing the candidate.

## Install or update

Download `app-release.apk`, compare its digest with `SHA256SUMS`, open it on
Android and choose Update over the stable-key installation. Do not uninstall a
working2.35 installation: a compatible update retains local data. Open the app
and check cached festivals/ratings; protect pending edits until confirmed sync.
Installation permission may be needed for the browser/file manager.

This remains the signed GitHub APK channel with manual updates. Android normally
blocks downgrades; prefer a higher-code corrective release. The lost historical
key compatibility exception remains separate. No key replacement, managed store
distribution or3.0 appearance redesign is included. The two previously accepted
stale Groma importer arrows and documented source-scanner limitations remain.
