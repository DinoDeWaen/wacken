# Wacken Planner 2026 V2.32

## Scope

V2.32 is an official signed Android release for metadata sync feedback and
group-wide festival lifecycle sync after V2.31.

Changes since V2.31:

- Adds visible task/status feedback for metadata enrichment so users can see
  provider work that is needed, running, done, skipped, or failed.
- Fixes the add-festival flow so signed-in festival creation uses Supabase plus
  Room instead of the local TSV fallback path.
- Adds Supabase-backed sync for festivals and festival lineup entries so a
  newly added active festival appears on another signed-in app after sync.
- Writes new imported bands through to Supabase and preserves existing
  non-empty golden-source band metadata.
- Makes active-festival rename and archive behavior group-wide by writing the
  festival lifecycle change to Supabase first, then updating the Room cache.
- Adds visible error handling when a group-wide add or rename cannot be written
  to Supabase.
- Documents the current group-wide festival data model in the README and
  business requirements.
- Bumps Android release metadata to `versionCode 35` and `versionName 2.32`.

No Supabase schema migration, schedule logic, automatic unreviewed fuzzy merge
behavior, metadata overwrite behavior, or Play Store distribution behavior
changed in this release.

## Signing And Installation

V2.32 uses the stable local V2.9+ release-key line managed by
`scripts/ensure-release-keystore.sh`.

Install it over a release that uses the same stable signing key. Devices still
using an APK signed before the stable key was introduced must uninstall the old
app once, install V2.32, and then sync from Supabase. Future releases signed by
this key will update normally.

MusicBrainz, Wikidata, and Wikipedia metadata lookup do not require API keys,
but production-like builds should provide a meaningful maintainer User-Agent:

```bash
MUSICBRAINZ_USER_AGENT="WackenPlanner/2.32 ( contact@example.com )" ./gradlew assembleRelease
```

Spotify enrichment is optional and requires `SPOTIFY_CLIENT_ID` and
`SPOTIFY_CLIENT_SECRET` at build time. YouTube enrichment is optional and
requires `YOUTUBE_API_KEY` at build time. Do not ship production Spotify secrets
in a broadly distributed mobile APK without moving token exchange behind a
backend.

## Known Non-Goals

- No Play Store distribution in V2.32.
- No Supabase schema change in V2.32.
- No automatic unreviewed fuzzy band merges.
- No automatic metadata overwrite behavior.
- No final Summer Breeze stages, performances, distances, or food import data.

## Accepted Risks

- Add-festival writes use the existing backend RLS policy: festival, lineup,
  and band inserts require a platform-admin account. Non-admin attempts now fail
  visibly instead of creating local-only data.
- Optional Spotify and YouTube providers require configured credentials; when
  absent, they are reported as not configured and the rest of the metadata
  workflow continues.
- Live external metadata availability is not guaranteed during festival field
  use; existing cached/catalog metadata remains available when lookup fails.
- Devices still using an APK signed before the stable key was introduced must
  uninstall once before installing V2.32.
