# Wacken Planner 2026 V2.34

## Included changes

- One shared canonical band catalog with metadata, confirmed aliases and music
  links. Exact identities are reused; nonexact imports require review.
- Separate personal established band ratings, festival planning ratings and
  festival after-ratings. Creation copies each member's established rating once.
  Archive promotes confirmed nonempty final after-ratings atomically; missing or
  reset after-ratings retain the previous established opinion.
- Explicit own archived rating correction with current-revision review,
  confirmation, immutable audit and original/correction date context. Older
  source corrections cannot overwrite newer established opinions or later plans.
- Active/archived detail labels the three rating contexts and source. Returning
  or rotating retains the opened festival; stale edits cannot target the next one.
- Separate own rating lifecycle CSV v2, preserving existing ratings/audit CSV
  contracts and detached/deleted history.
- Verified YouTube/Spotify discovery from Settings for a festival or band detail,
  evidence review and explicit approval. Unknown links stay empty.
- Local CSV grid review with selected-row application, validation, cancellation,
  stale-review detection and transactional rollback.
- Metadata-independent canonical joins for group votes and schedule context;
  scheduling continues to use the selected festival's planning votes only.
- Android6/API23 storage/UTF8 compatibility, full lint and native CI on API23/36.
  Existing atomic Summer Breeze creation and unknown-channel hotfixes remain.

The approved Ironline dark / Field Notes light redesign is planned for **3.0**.
This release keeps the current native appearance.

## Install/update

Download **app-release.apk** from this GitHub release and install it over the
current stable-key release. Package identity and signing certificate are unchanged.
Update without uninstalling or clearing storage so auth, cached metadata/history
and pending work remain available. Unknown/ambiguous legacy outcomes stay retained
and require review; active history does not automatically establish a band rating.

Distribution remains signed GitHub APKs, as selected by the release owner.
There is no automatic update service, Firebase enrollment or Play testing channel.
The older lost signing-key line cannot update in place; protect local-only data
before any one-time recovery reinstall.

## Limits

Exports reflect cached sync state. Unknown dates are not invented. Another
device's unsent work cannot be inspected during archive; it remains pending for
explicit recovery/correction. Local CSV fallback changes may refresh from central
sync; no offline archived-correction queue is added. Music sources need configured
provider access where documented, and only evidence-approved links are saved.
Physical-device external YouTube/Spotify app interaction is not part of emulator
validation. Pre-existing Supabase advisory findings are tracked in TASK224;
new rating/alias/audit tables enforce RLS and authenticated operations.
