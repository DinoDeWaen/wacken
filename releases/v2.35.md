# Wacken Planner2026 V2.35

Maintenance release for the existing signed GitHub APK channel.

## Changes

- Bound authenticated rating/schedule HTTP connect and inactive-read waits while
  preserving auth retry, member ownership and pending operations.
- Close/cancel band-image requests safely and suppress stale screen results.
- Use consistent backend error-message precedence and canonical band lookup.
- Reuse festival-scoped rating projections and reviewed detail presentation
  while retaining active/archive editing distinctions and unknown links.
- Remove the unused full CSV importer; the active row-review/rollback path keeps
  its characterization coverage and shared input/result values.
- Version and curate runtime/data boundaries and lifecycle scenarios. The map
  has95 responsibilities,294 owned source files and no unexplained component
  islands. The pinned development gate protects reviewed ownership,
  relationships, flows, duplicate identities and scanner diagnostic limits.

The established-band/planning/after-rating lifecycle remains ADR0016. This is not
the separate3.0 appearance/navigation redesign. Intentional typed mappings,
constructors and distinct business policies remain; lint similarities are not
treated as automatically confirmed defects.

## Validation and retained limits

The [integrated matrix](https://github.com/DinoDeWaen/wacken/blob/v2.35/backlog/docs/release-2.35-validation.md)
accounts for F1-F10 and every historical99-group lint disposition. The final
release evidence binds JVM/BDD/coverage/lint, API23/API36 native, disposable
PostgreSQL/PostgREST, architecture and signed latest-stable preservation gates
to the release source and exact APK. Existing environment-gated unit integration
cases are covered by the dedicated real database/API gate, not claimed as unit
passes.

Two historical authored arrows involving the deleted importer remain an explicit
user-accepted Groma tooling limitation. They are reported as stale claims; the
deleted file has no ownership or flow use. Java-only scanner warnings are not
application compiler failures. Source, SQL and rendered-map review remain
necessary. The [ArchUnit assessment](https://github.com/DinoDeWaen/wacken/blob/v2.35/backlog/docs/architecture-tool-assessment-2026-10-21.md)
recommends it as a complementary Java boundary-testing option; no new Java
library was added.

## Install or update

1. Download `app-release.apk` from this release and compare its SHA256 with
   `SHA256SUMS`.
2. Open it on the Android device and choose Update over the existing stable-key
   installation. Do not uninstall a working2.34 installation to update.
3. Open the app and check cached festivals/ratings; pending changes remain until
   confirmed sync. The signed release probe checks login/cache, own/other member
   opinions, festival planning/after values, dated history, immutable corrections
   and normal offline startup over the actual published2.34 APK.

Android can require installation permission for the browser/file manager. This
channel does not provide automatic updates or Play/Firebase enrollment. Older
installations signed by the lost historical key remain a separate compatibility
case; no key replacement is part of this release. Android normally prevents
downgrades: prefer a later higher-code fix and protect pending/exported data
before considering any reinstall. Never wipe user data to force an update.
