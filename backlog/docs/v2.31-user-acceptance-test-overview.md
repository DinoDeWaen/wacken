# V2.31 User Acceptance Test Overview

Date: 2026-08-25

Related tasks: task-179, task-179.1, task-179.2, task-179.3, task-179.4,
task-179.5, task-179.6, task-181

## Purpose

Validate the V2.31 signed release for reviewed band linking and metadata
enrichment. V2.31 focuses on keeping the local band database as the golden
source, requiring review before links or metadata are saved, and adding external
metadata proposals from MusicBrainz, Wikidata, Wikipedia, optional Spotify, and
optional YouTube.

## Prerequisites

- Install the signed V2.31 APK from the GitHub release.
- Use an app state with an active festival containing imported bands.
- Include at least one imported band whose spelling/casing differs from an
  existing catalog band, for example `Any Given Day` vs `Any given Day`.
- Include at least one band with missing biography, image, Spotify, or YouTube
  metadata.
- Optional: build with `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET` to test
  Spotify enrichment.
- Optional: build with `YOUTUBE_API_KEY` to test YouTube enrichment.

## Acceptance Overview

### 1. Reviewed Imported-Band Linking

1. Open Settings.
2. Open the link-bands review workflow.
3. Find the imported spelling variant, such as `Any Given Day`.
4. Review the editable search term and candidate selector.
5. Select the existing golden-source band or choose `No match`.
6. Save the approved decision.

Expected result:

- Likely matches from the existing band database are offered for review.
- No link is applied without explicit user approval.
- `No match` leaves the imported band separate.
- An approved link reuses the existing band identity, ratings, history, picture,
  biography, Spotify link, and YouTube link.

### 2. Own-Catalog-First Metadata Enrichment

1. Ensure a band is missing at least one metadata field.
2. Ensure a likely existing catalog band has a value for that missing field.
3. Open Settings.
4. Run the metadata enrichment workflow.
5. Review the proposed values.
6. Save only selected proposals.

Expected result:

- Own band database proposals appear before external-source proposals.
- Saved proposals fill only blank fields.
- Existing non-empty biography, picture, Spotify, or YouTube values are not
  overwritten automatically.

### 3. Reviewed External Metadata Proposals

1. Use a band that still has missing metadata after the own catalog is checked.
2. Run metadata enrichment from Settings.
3. Review proposals from MusicBrainz, Wikidata, Wikipedia, Spotify, or YouTube
   where available.
4. Select only trusted proposals and save.

Expected result:

- External values are shown with their source and candidate context.
- MusicBrainz can propose Spotify and YouTube URL relationships.
- Wikidata can propose structured image, Spotify, and YouTube claim values.
- Wikipedia can propose neutral biography text and page-summary images.
- Spotify proposes artist URL and image values only when configured.
- YouTube proposes channel URLs only when configured.
- No external value is saved until selected by the user.

### 4. Optional Provider Configuration

1. Run metadata enrichment without Spotify credentials or a YouTube API key.
2. Review the status messages.
3. Repeat in a configured build if credentials are available.

Expected result:

- Missing optional Spotify configuration is reported as `Spotify is not
  configured.`
- Missing optional YouTube configuration is reported as `YouTube is not
  configured.`
- Public providers continue to run when optional providers are not configured.
- Configured optional providers return candidate proposals without requiring a
  user Spotify or YouTube login.

### 5. No-Overwrite Regression

1. Pick a band that already has biography, picture, Spotify, or YouTube data.
2. Run metadata enrichment.
3. Save unrelated missing-field proposals, if any.

Expected result:

- Existing non-empty metadata remains unchanged.
- The workflow does not offer automatic replacement behavior.
- Replacement of existing metadata remains out of scope unless a future
  reviewed replace workflow is added.

## Acceptance Decision

Accept V2.31 when the tester can confirm reviewed linking, own-catalog-first
metadata proposals, external provider proposal review, optional provider
configuration handling, and no-overwrite behavior. Reject or hold the release if
any workflow saves a link or metadata value without explicit review.
